# ADR 0011：读板书靠选对帧，看图交给用户的视觉 AI（P5）
状态：已采纳（2026-10-11，浩提出需求，架构师定方案）

背景：浩指出大学课程视频常常讲得少、重在板书，读取画面是核心目标。审查核查现状：仓库没有任何读画面文字的能力；场景检测 `gt(scene,0.3)` 只在画面突变时触发，一笔一笔写的板书基本触发不了；索引概要只来自转写。浩说明不要 OCR，他接入的 AI 都是视觉模型。

决策：
1. 选帧：每 2 秒抽低分辨率灰度图算感知哈希，按"稳定一段后出现大变化"切区间，每个区间取变化前的最后一帧（擦黑板或翻页前）；与原场景检测结果合并去重；讲话少的时段自动加密抽帧；间隔与阈值写进配置。
2. 索引里把每个板书区间列成一类段落：时间范围、帧编号、同时段转写。AI 按需用 `get_frame` 取图。
3. 图片规格：长边默认 1280，JPEG 质量 85，可配置；`get_frame` 支持一次取多张，单次最多 4 张。
4. 本地视觉模型 `ToolId::Vision` 默认关闭，只用于不能看图的客户端或生成一句话画面概要；提示词带上一帧描述、只写新增内容、读不清标"[看不清]"。
5. 验收：主指标帧覆盖率（每题答案所在板书至少被一张选中帧完整、清晰地拍到）；辅助指标每小时选帧数（越少越好）；编造率只在启用本地视觉模型时测。
6. 效果集补 PPT 课与黑板课各一段，许可证合适即可只用于评测。

放弃的备选：RapidOCR 等本地 OCR（浩明确不要；视觉 AI 能读公式、手写与图表关系）。
未验证的前提：ChatGPT 网页版等客户端是否把 MCP 返回的图片交给模型看，写入本地测试方案由浩在 4060 实测；不支持的客户端改用本地视觉概要。
已知限制：公式与手写识别依赖用户所接 AI；本地 CPU 只能做功能验证。
