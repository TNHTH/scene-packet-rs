# ADR 0008：交付范围与 P3 准入条件
状态：已采纳（2026-10-11，质疑提出，架构师确认）

交付范围：核心库与 CLI/MCP 优化完成；GUI（`App.svelte` 及实际界面行为）未在 Windows 上手动运行，未验证。交付说明与签字均按此范围，不得更宽。

P3 调整：
1. 先修 ASR 指纹：模型与 whisper 可执行文件改用内容指纹（大小 + 头尾各 1MB 的 xxh3），不含路径；补回归测试。原实现的问题：模型只存路径字符串（同路径换模型仍命中），可执行文件用"大小:修改时间"（重装即全部失效）。
2. 新增 P3-0 效果集，作为 P3-2 准入条件：2–3 段许可证允许的短视频，每段 5–6 题，标注答案所在时间段或帧；先测"给定 token 预算内是否包含答案段"的可复现下限，端到端作答模型固定并记录。
3. P3-2 准入：效果集上答对题数不少于直接返回全文；短视频直接返回全文的阈值 N 由效果集确定；若实测主流客户端不主动调取，P3-2 只保留"长视频超出上下文才切分"。
4. P3-1 基线仅防结构回退，字节数与 token 数是成本指标，不代表质量。

## 修订（质疑提出，架构师确认）
- 下限指标改为"只看索引，正确的段能否排进前 2"（题目对段概要做关键词或向量匹配）；原"返回内容是否包含答案段"对 compact/full 恒为 100%，作废。
- 段概要只用非大模型方法：TF-IDF 段内关键词、头中尾各一句，两者用新指标比较；核心库不调用大模型。当前实现为"首句前 40 字"。
- 两种方法都排不进前 2 时，索引模式永久为可选，P3 收尾进入签字。
- 签字条件：索引模式成为默认前，效果集答对数不少于 compact；仅报 token 减少不够。
- `MediaKey`：私有字段，只能 `MediaKey::parse`，不实现 `From<String>`/`Deref<Target=str>`，路径统一 `MediaKey::dir(&root)`。rmcp 暂不升级。`avr-mcp` 补进程内 MCP 集成测试，穿越用例走真实链路。
