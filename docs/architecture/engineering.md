# 当前工程边界

日期：2026-10-12。基于四 crate 架构继续收敛实现；历史 P1 设计保留为设计记录。

- `avr-core`：媒体身份、流水线、缓存、进程、选帧和导出。`analyze(ctx, Source, AnalyzeOptions, Deps)` 是分析入口；`Deps` 注入 `JobManager` 与 `Tools`。
- `avr-mcp`：协议、分页、索引、响应体。索引一次生成章节和帧引用；视觉获取复用核心下载与截帧函数。
- `avr-cli`：命令参数与输出；不依赖 Tauri。
- `desktop`：同一个 `PipelineContext` 保存数据根和配置。Tauri 命令负责转换错误；Svelte 状态使用 runes，先注册事件再允许任务启动。

## 共用实现

`storage` 统一完整流式 SHA-256 和原子文件替换；`jobs::FileLock` 统一操作系统文件锁。同步公共函数保留兼容入口，流水线的大文件哈希和同步工具探测在 Tokio blocking 池运行。完整内容哈希仍需读取整个文件，不宣称无 IO 成本。

子进程同时排空 stdout/stderr，超过保留上限继续读取，避免管道死锁。取消/超时回收进程；Unix 使用独立进程组，Windows 使用 taskkill。工具安装先暂存、验证必需文件，再提交目录并在普通失败时恢复旧版本；多目录提交不具备断电事务保证。

## 缓存与视觉一致性

本地媒体键使用完整内容 SHA-256。复制同内容文件可复用转写，当前文件的绝对路径重新绑定为视觉源。BV 号保留标识部分的大小写并区分 `p`，不再扫描旧缓存猜测归属；旧键会发生一次缓存未命中，旧文件保留。

ASR 模型身份使用完整内容 SHA-256。选帧缓存同时比较算法版本、参数和转写摘要。采样通过一次 FFmpeg 解码产生灰度像素及对应 framecrc 时间戳，变帧率视频保留实际 PTS；回截保留微秒精度，不把时间四舍五入到毫秒。

URL 截帧按需下载完整时间轴的低分辨率视觉源，验证有视频轨道后再提交缓存。不复用来源和偏移未知的旧 `clip.mp4` 或限长代理。下载依赖平台可用性和用户 Cookie，不保证远端服务始终可用。

图文包逐帧写 HTML，避免同时驻留全部 base64；全部产物先暂存再提交目录，失败可重试同一输出路径，非空成果目录不会被覆盖。实际图像宽高从图片头读取。数据根迁移要求停止相关作业，先复制到同盘临时目录并校验文件内容，再切换指针；原目录保留，非空目标和相互包含路径会被拒绝。

## 验证入口

```sh
python3 tools/check.py
(cd desktop/ui && npm ci && npm run build)
cargo clippy --workspace --all-targets -- -D warnings
```

CI 覆盖 Rust 1.88、stable、Windows desktop。`AVR_REQUIRE_FFMPEG=1` 要求真实 FFmpeg 集成测试执行，不能跳过。Python 工具回归只使用合成 Cookie。真实模型识别质量、用户平台认证、桌面原生拖放/窗口效果需在目标宿主另行验证；编译和进程内 MCP 测试不能代替这些验证。
